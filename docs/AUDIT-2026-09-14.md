# The fifth pass — a find-and-fix sweep, 2026-09-14

`AUDIT-FINDINGS.md` is passes 1–6: two read-only scans by a second session, 50 findings, 17 fixed.
**This is a different kind of pass and the difference is the point.** It was asked for as "a
complete bug hunt… every kind of bug you can find", then widened mid-session to "pretend you are
pentesting the website" and "pretend you are a web developer… fix everything you can". So it
finds *and* fixes, and where a fix is security-shaped it was **break-verified** — the test was
watched failing against the old code before the new code was believed.

**Everything here is new.** Each reviewer read `AUDIT-FINDINGS.md`'s index first and was told that
anything already listed there, or documented in `CLAUDE.md` as deliberate, did not count.

## What made this pass different: it ran things

Passes 1–6 were source reads, and the standing "still needs a person" list is what source reads
cannot reach. This pass closed part of that list by driving the real things:

- **The Worker under `wrangler dev`**, with `scripts/auth-e2e.ts`'s own fetch shim and the **real**
  `src/auth` browser modules — so a claim about rate limiting is a measured HTTP status, not a
  reading of the arithmetic.
- **The setup scripts' blocklists executed**, sliced out of the shipped scripts and run against
  throwaway home directories (one symlinked, one with a space in its name), plus the PowerShell
  under `pwsh`.
- **The site in a browser**, via `sitelab.html`'s iframe, with forced calm defeated — all fourteen
  layouts at desk and every route at the phone band.
- **The duel's flaky gate reproduced and diagnosed**, over 3,600 simulated duels.

One early scare is worth recording because it was *not* a bug: the auth suite killed the Worker
twice mid-run, at the same point both times. It looked like a crash in the rate limiter, reachable
unauthenticated. It was a parallel reviewer in this same session stopping the Worker to inspect a
build. Re-run in isolation the suite passes end to end. **A reproducible-looking failure under
concurrent agents is not reproducible** — this is the one shape of false positive this method adds,
and it is worth naming.

## Fixed — security and correctness (`worker/`)

**1. An anonymous stranger could lock the operator out of every password-proven route.**
`worker/accounts.ts`. `signin` and `assertPassword` derived the **byte-identical** bucket name
`account:hmac(handle)`, and both reserved before checking anything. So six wrong-password POSTs to
`/api/auth/signin` — from anybody who knows a handle — blocked, the penalty doubled to the
hour-long ceiling, and roughly one request an hour held it there indefinitely. The cap on
`MAX_PENALTY_MS` bounds *one* penalty, never the repetition, so the comment claiming it prevents a
denial of service was wrong. For the owner that took down `publishSiteConfig`, all five admin
writes, the six release-gated downloads routes, `keySlot`, `changePassword`, TOTP enrolment and
confirmation, passkey register and remove, and `machines.pair` — **while signed in, including
signed in with a passkey**, which has no rate limiting at all.

The fix splits the namespace: a password *re-proof* reaches `assertPassword` only through
`requireAccount`, so it now uses `proof:hmac(handle)`, which an unauthenticated caller cannot fill.
The allowance is unchanged at five, so a stolen cookie grinding the password is throttled exactly
as before. **Break-verified**: against the old code the probe reports `keySlot FAILED: Too many
attempts`; against the new one, `keySlot OK` while the sign-in bucket is blocked at attempt 7.

**2. A successful sign-in left the caller blocked.** `worker/rate-limit.ts`. `attempt()` reserves
up front and promises everything after the allowance is blocked "until refunded"; `succeed()`
decremented `failures` and never cleared `blockedUntil`. So the 51st request from a household
behind one NAT being the *correct* password armed a 15-minute block, and the person who had just
signed in successfully was refused every credential route for the rest of the window. The block is
now lifted when the refund brings the count back inside the allowance — a run of genuine failures
still stands, so the credential-stuffing defence is untouched.

**3. A code for a file that can never open it still redeemed, and burned a use.**
`worker/downloads.ts`, `opened()`. The file-scope branch returned `items: [id]` even when it had
just computed that the page is `granted`, or a draft, or not live — and `claim`'s emptiness guard
is satisfied by `items` alone. So the redemption succeeded, incremented `uses`, and handed back a
ticket that 403s at the first byte. The customer sees success, gets nothing, and burns all five
uses one empty success at a time. The old comment reasoned that the entry was "already inert" and
only the *name* needed withholding; inert is exactly what made keeping it wrong.

**The same fix closes `AUDIT-FINDINGS.md` #13** (routed as judgment work, never done): a file whose
bytes never finished uploading is the same case — `uploaded_at` is null, `readPage` hides the row,
`canDownload` refuses it. Two new e2e assertions cover it, and the existing fixture was made
realistic: it created a file row and never uploaded bytes, so it had been asserting *"a code for a
half-finished upload opens it"*, which is the bug rather than the rule.

**4. A filename with a lone surrogate saved cleanly, then 500'd on every click, for ever.**
`worker/downloadPages.ts`. Neither filename guard rejected an unpaired surrogate, and `extValue`'s
`encodeURIComponent` throws `URIError` on one — not a `BadRequest`, so it renders as a generic 500
on `GET /api/downloads/file`, on a row that lists normally with a working button. The editor sends
`file.name` straight from the `File` object, so a Windows filename with damaged UTF-16 carries one
through. Refused on the way in now; **refuse, never repair**, because `toWellFormed` would store a
different name from the one on the operator's disk.

**5. `REACH` was indexed without an own-property guard.** `worker/downloadPages.ts`.
`REACH["constructor"]` returns a function from `Object.prototype`, so `?? -1` never fired, the
comparison ran against `NaN`, `widens` collapsed, and the **release password was silently not asked
for** on a live page going public. Not reachable through `savePage` today; it is the same prototype
walk that took the site down in `validDuelPages` (audit item 40), closed the same way.

**6. Trailing slashes minted an unbounded family of self-canonicalising indexable pages.**
`worker/page-meta.ts`. `pageFromPath` strips trailing slashes, so `/contact/` resolved to `contact`,
got no `noindex`, and emitted a canonical pointing at **itself** — as did `/contact//` and `//`. The
canonical now comes from `PATHS`, a total map from a closed union. Verified live: `/contact/` and
`/contact` both canonicalise to `https://mcclevarty.ca/contact`.

**7. Ids were read raw where their writers normalise them** (`AUDIT-FINDINGS.md` #14, left
outstanding). `addGrant` and `mintCode` read `str(b.item, 64)` while `saveFile` lowercases before
storing, so a grant typed `Boot-Repair` found no row and answered *"No such file."* for a file
plainly in the list. Both go through `fileId` now, which its own comment already named as the rule.

**8. Unbounded arrays reached `DB.batch` and R2.** `reorderPages`, `reorderFiles`, `uploadPart` and
`finishUpload` took caller-supplied arrays with no cap, where the sibling `saveBlocks` caps at 40
with a comment saying why. Past D1's batch limit that is a throw rendered as a 500 where the code
means "no". Capped, and `finishUpload`'s parts are now shaped — it mapped `Number(x.part)` and
`String(x.etag)` straight through, so a missing field became `NaN` and an object became
`"[object Object]"`, both of which R2 answers with a throw.

**9. `finishUpload` never checked `meta.changes`.** A `deleteFile` landing mid-upload left
`upload.complete()` having written the object *after* the delete removed it — orphan bytes under an
id `suggestFromFilename` hands out again — and the handler answered `{ok: true}`. It now cleans up
and tells the operator the row is gone.

**10. Live codes and grants could become permanently unrevokable.** `listCodes` and `listGrants`
were `ORDER BY created_at DESC LIMIT 200` with no paging in the UI, while revoking requires a `ref`
the operator can only read off that list. Codes default to five uses and **never expire**, so past
200 newer rows every older live code fell off the end — silently, through the only withdraw control
the feature has. Live rows now sort first: a dead code needs no withdrawing, so it is the one that
may fall off.

**11. The handle pattern did not enforce the DNS safety its own reason rests on.**
`/^[a-z0-9][a-z0-9-]{2,23}$/i` accepted `abc-`, `a--b` and `xn--abc` — a reserved IDNA prefix. The
comment says this becomes a breaking migration once accounts exist, so it was fixed while it is
still free.

**12. `assertPassword` consumed an attempt before validating the secret's shape**, so a truncated
paste burnt one of five with no refund and answered 400 rather than 401.

**13. `Host` was trusted in two places with a grammar.** `worker/index.ts`. `;` is not a forbidden
domain code point, so `Host: a;script-src 'unsafe-inline';b` would have written directives into
`connect-src`, and `Host: www.evil.com` would have 301'd a visitor to `evil.com`. Unreachable
behind the route bindings — but the stated safety argument for the concatenation was about redirect
*loops*, not host trust, so the next reader had nothing to rely on. A `safeHost()` helper now gates
all three sites.

**14. `rename()` 500'd where its sibling `pair()` returns a clean 409.** `worker/machines.ts`. It
had the pre-check and not the catch, so a name collision surfaced as an unhandled exception on the
owner's own screen. The `COLLATE NOCASE`-versus-binary-index race behind it still wants a migration
and is left in the backlog rather than half-done.

## Fixed — the customer-facing setup scripts

Three of these expose credentials and all were reproduced by execution.

- **A prefix blocklist entry left the directory itself shareable** (`windows-share-setup.ps1`). The
  test was `StartsWith($bad + '\')`, false when the path *equals* the entry, and five entries are
  prefix-only — so `~/.ssh`, `.aws`, `.gnupg`, `.docker` and `.kube` were **ALLOWED** while their
  children were refused. The script junctions what it is given into the share root and the page
  tells the customer to pick that root as one folder, which Chrome reads through the junction. The
  Unix scripts never had this. Both existing gates were green throughout: one reads the array as
  *text* and the other drives only the reparse-point resolver, never `Test-ShareableFolder`.
- **A symlinked `$HOME` defeated every `$HOME`-derived entry** (Linux and macOS). The input was
  canonicalised; the entries were not. With `/home` a symlink — a separate data partition, NAS
  homes, `/export/home` — `$HOME`, `~/.ssh`, `~/.gnupg`, `~/.config` and `~/.local` were all
  **ALLOWED**.
- **`/tmp` was inert on macOS**, because it canonicalises to `/private/tmp`, which matched no entry.
- **`--folders` was glob-expanded**, so `--folders "$HOME/Notes[1]"` linked and advertised
  `Notes1` — a *different folder* — with no warning, and `"$HOME/*"` linked the whole home.
- **Four ways to produce a code the site then refuses**, all landing *after* the links are made:
  label de-duplication that did not use the decoder's fold, characters the decoder refuses that no
  script warned about, a path length checked before canonicalisation, and no check against
  `MAX_CODE` at all (24 deep folders produced an 8,279-character code).
- **Control characters were stripped from the *path***, so a folder named `Doc\numents` emitted a
  path that does not exist — or worse, one that does and is a different folder.
- **`--undo` did not see dot-named links**, removed the marker anyway, and then refused to touch the
  folder ever again — so a shared hidden folder stayed shared permanently.

## Fixed — the host provisioning scripts

- **The kiosk URL allowlist could be turned into `["*"]`.** The host was validated with a per-line
  `grep`, so a multi-line url file produced a host that passed, generated **valid JSON** — `jq`
  approved and the state variable reported success — and disabled the navigation lockdown on the
  machine that autologins into the browser holding the directory handle. Character for character
  the exploit the neighbouring comment claims to have closed, rebuilt through the next field.
- The same path's failure branch ran **before** `configure_firewall` and `harden_ssh`, so an
  ordinary two-line file left the box with no ufw and root SSH still permitted.
- **`plasma --restore` extracted a whole tarball into `$HOME`** while claiming it restores "just
  these" files — one carrying `.config/systemd/user/vessel-kiosk.service` replaced the kiosk unit.
- Several `|| true` swallows where the next line reported success unconditionally (the Chromium

  *successful* match as failure.

## Fixed — the browser half

- **The operator's hero ornament never changed for a whole session.** `operatorRoll` was cleared
  only by `update()`, while `shuffle`, `setMode`, navigation, popstate and the mount roll all call
  `setConfig` directly. Shuffle announced a new combination, every other dial moved, and the
  ornament sat still — the exact 2026-08-27 symptom shape.
- **The downloads index did not reset scroll.** `/downloads/<name>` changes only `sub`, and the
  scroll/title effect depended on `[config.page]` alone, so clicking a program card rendered the
  program page at the index's scroll offset. On the only commercial surface on the site.
- **Back/forward played no transition at all**, left the panel open over a different page, and — for
  300ms after any click — a pending commit pushed the page you had just left, destroying the forward
  entry.
- **Share codes repaired instead of refusing.** `pal` and `type` were `Math.min`-clamped where every
  other field falls back to a named default, so a mistyped code applied cleanly and pinned the
  recipient to Cold Open. "A working code pointing at the wrong palette" is the failure this file is
  gated for.
- **Shift+Arrow paged the site** (the text-selection gesture), autorepeat left the stage diving on
  the old page until key release and fired the nav chime ~30×/second, and the keystroke buffer
  recorded modifier presses so any shifted character silently broke `sudo`.
- **Focus return was not gated on being the top trap**, so closing a lower layer yanked focus out of
  an open modal.
- **The duel pin editor offered pairs the validator refuses** — same-side fighters, which publish
  and are then silently dropped for every visitor while the operator's own checkbox unticks itself.
- **The agent-key-changed prompt had no accessible name, no focus move and no trap** — the one
  prompt on the site where "the user must read it before answering" is a security property. It is a
  real `Dialog` now, with refuse as the default.
- **A live region wrapped the whole machines page**, so every folder navigation queued a 2,000-row
  directory listing for announcement.
- **The blob download raced its own revoke**, intermittently for large files — the terminal step of
  the whole phase-2 browse.
- Swallowed failures and missing in-flight guards on grant add/remove and the four sharing-page
  writes: a double-click created duplicate grants or an orphaned drive, and a *failed* revocation
  looked identical to a successful one.

## Fixed — the sharing protocol

- **No ICE candidate queue on either side.** Both ceremonies emit candidates before sending the SDP
  that lets the peer accept them, with a real WebCrypto hop in between, and neither side serialises
  frames. Early candidates were dropped — so a LAN pair limped on peer-reflexive discovery or timed
  out, and the 20-second timer blamed NAT for a dropped-message bug.
- **A binary frame shorter than 8 bytes threw uncaught** inside the channel handler, and because no
  request in the file protocol had a timeout, the read never settled.
- **A large directory listing was one `send()` with no byte bound**, and the throw was swallowed:
  2,000 entries measures 285KB at 80-character names against Chrome's 262,144 limit, so an ordinary
  photo folder left the explorer on "Listing…" for ever.
- **A failed pin write after a successful dial leaked the whole connection** and reported "Could not
  connect" carrying a raw IndexedDB error.
- `isValidPath` used `every`, **which skips array holes**, while the agent's walk does not.

## Fixed — the duel's flaky gate, with a verdict

The open, unchased flake (`duel: the health bar clears every costume`) is **the gate's fault, not
the renderer's**, and neither hypothesis on record was right. It is not "airborne fighter" — it is
misattribution. The gate maps a recorded bar to a fighter by coordinate, which is ambiguous when
`st.a.x === st.b.x` *exactly*, and the arena wall clamp makes that reachable: both fighters clamp to
the identical value and the body-separation resolve that would split them is skipped whenever either
is airborne. Both bars then map to `st.a`, so `st.b`'s bar is judged against `st.a`'s headroom.

The renderer is provably safe over all 24 declared `headroom` values, by arithmetic, on every frame.
Measured rate 0.31% per duel, ~3.6% per gate run — exactly the "failed once, passed either side"
signature. Fixed by attributing on draw order. **It was explicitly not fixed by exempting an
airborne fighter**, which would mask the ambiguity and stop testing the bar during the frames the
camera is under most stress.

## Fixed — web quality

- **192KB of webfonts and 2.0MB of photographs were revalidated on every cold navigation**, because
  only `/assets/*` had a cache rule, while the 512KB bundle beside them was `immutable`. Both
  families now carry a week with `stale-while-revalidate` — deliberately **not** `immutable`, since
  these filenames carry no content hash, which is the whole property that makes `/assets/*` safe.
- **A white flash on every cold load**: `color-scheme: dark` lived only in the render-blocking
  stylesheet, which still lands after the UA paints its own canvas, against palettes whose brightest
  background measures 0.0104 relative luminance. `color-scheme` and `theme-color` are in the shell.
- Six controls whose only visible boundary was `--line` (1.19–1.61:1) now use `--edge`; the command
  palette's input and the phone nav no longer clip their focus rings; `.v-file-name` meets WCAG
  2.5.8; the phone filter controls meet the 44px floor the swap to them was argued from; `.v-shock`
  centres with `translate` so calm does not strand two rings over the door.

## Found and deliberately NOT fixed

- **`beginUpload` can dark a live download without the password.** It is session-gated and sets
  `uploaded_at = NULL`, which `finishUpload` (password-gated) is the only way to undo — so a dropped
  connection mid-replacement takes a published file offline while the old bytes sit intact in R2.
  This is already `TODO.md`'s *Needs the client* item 3, and the fix named there ("keep the old
  bytes live until `finishUpload`") is a product decision about the editor's flow.
- **Sessions still survive a password change and an operator reset** — `TODO.md` item 2, a §9
  inventory change and therefore his call.
- **The `COLLATE NOCASE` / binary-index races** in `setups.ts` and `machines.ts` want a migration.
  `rename()`'s missing `try`/`catch` is fixed; the underlying index is not.
- **A signalling socket is authenticated once and never again**, and `admin.deleteAccount` never
  hangs up. Bounded by the agent still verifying the peer's grant-key signature, so what survives is
  relay and presence, not file access. Wants the same decision as item 2 above.
- **`code`-visibility pages are publicly enumerable with title and summary.** Consistent with the
  stated rule that "a `code` page says it exists", but it sits against the reason `granted` pages
  404. Worth a line in `docs/DOWNLOADS.md` telling the operator to name `code` pages neutrally.
- **The download ticket is a 30-minute bearer token in the URL query string** — a deliberate
  consequence of the link having to work for `curl -C -`. Recorded as accepted, not unnoticed.
- **The 2.0MB of photographs re-encode to 728KB at 900px/q72/progressive**, same format, same
  colour, no CLS risk. Left alone: it changes shipped assets and `docs/PHOTOS.md` is a ledger.
- **~29% of the 512KB bundle is operator-only** and could go behind one `React.lazy` boundary.
  Deferred as an architectural change, not a bug.
- **`npm audit`: 3 high, all dev-only** (`sharp` → `miniflare` → `wrangler`). `--omit=dev` is clean;
  nothing vulnerable ships.

## Gates

The suite went **82 → 86**, and the four added are the ones that drive the thing rather than read
it. **Every fix above that could be gated wants one, and the crews wrote specs for roughly forty
more** — they are in this session's record and are the obvious next session's work. Three are worth
naming because the existing gate was *green throughout the bug it is named after*:

1. **The Windows blocklist gate never calls `Test-ShareableFolder`.** It reads the entry arrays as
   text and drives only the reparse-point resolver. That is why a prefix entry which did not block
   its own directory sat there with two gates passing. This is the 2026-09-03 lesson — *a gate that
   reads the source is testing the source's shape* — one function over.
2. **Nothing gates the deploy shape.** No check mentions `_redirects`, `_headers`,
   `rollupOptions`, `fxlab`, `sitelab` or `run_worker_first`. Audit item 39's fix — whose absence
   served a frameable, nonce-less, year-cached copy of the shell at any `/assets/<name>` — exists
   only as a comment in `wrangler.toml`. Re-adding a negation passes all checks.
3. **Nothing gates `src/hooks` at all.** `useOperatorRoutes`, `useAccountRoutes` and `useFocusTrap`
   appear nowhere in `check.ts`, and three of this pass's findings are in them.
